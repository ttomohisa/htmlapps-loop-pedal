# Loop Pedal — Offline and Local Audio Verification

This is a **manual test plan**, not a statement that every environment has passed.

## Local single-HTML builds

1. Run `build-standalone.bat` on Windows. Verify that the normal
   `dist/index.html`, the self-extracting `dist/index.self-extract.html`,
   and the repository-root `loop-pedal.html` are generated.
2. Check `dist/build-size-report.json` and the normal template verifier.
3. Open both variants directly using `file://` in current Chrome and Edge.
   Verify that the favicon matches the header icon, including the self-extract loader.
4. Confirm the main page loads without requesting microphone permission.
5. Open the browser console. Select **Enable microphone** and grant permission.
   If the platform blocks microphone access or AudioWorklet loading from `file://`,
   record the exact browser version, message and restriction. Do not call this a pass.
6. Record one pad after the count-in. Save a named WAV and check its RIFF header
   and sample duration. Try multiple tracks, mute, Undo and re-record.
7. Turn network access off. With the local HTML loaded, repeat core operations.
   In the Network panel confirm **no audio upload, API, font or remote script request**.
8. Verify cancellation and document visibility handling. An interrupted
   uncommitted take must not replace a finished take.

## HTTPS preview

Use the pull-request Preview URL generated by the repository's normal Cloudflare
workflow, if credentials are configured. On Android Chrome and iPhone Safari:

- Test mic permission, count-in, 4-track capture and WAV download.
- Test headphone layering and phone-only silent capture.
- Test backgrounding, lock, calls and disconnect/reconnect; inspect the save state.
- Test 320px and 360px widths, both UI languages, dialogs and access via keyboard.
- Record samples / devices / audio routes / measured compensation separately.
- Check CSP and runtime requests after the initial HTML has loaded.

## v0.3.0 smartphone regression checks

- Scroll halfway down, open “使い方と注意事項”, then try scrolling behind
  it with both touch and wheel. Only the help body should move.
  Close with the button, Escape, and by touching the backdrop; confirm the
  page returns to its previous scroll position.
- At narrow smartphone widths confirm the footer is hidden, the privacy badge
  reads 「完全ローカル処理」, the header subtitle describes recording/looping,
  and the English-to-Japanese switch reads **JA**.
- Try the ±5 ms timing buttons and the 0 ms reset on a committed track.
  WAV export and audio playback must respond to the same adjusted position.
- Record loud short attacks near the beginning and end of a loop. Inspect the
  seam with signal analysis and listen for noise/pumping before accepting the
  four-millisecond correction. Source PCM and downbeat sample must be unchanged.
- Audio diagnostics may report browser output latency. It must **not** describe
  that number as measured microphone latency or detect headphone connection.
- Change audio device or unplug a mic while a take is recording. No incomplete
  take should replace a previous completed take; stale events must not stop
  newly connected audio streams.

## Latency, acoustic output and limitations

`connect-src 'none'` prevents normal runtime connections, but does not prove
that device latency is small. Test an external signal/loopback reference for
timing: do not substitute human hand claps for a calibrated measurement.

Browser availability of `file://` microphone/AudioWorklet is device-dependent;
the fact that the HTML is self-contained does not guarantee microphone access
from all local file contexts. See `ACCEPTANCE_MATRIX.md` for the release gate.
